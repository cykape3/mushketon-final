# Настройка своей копии (один раз)

Эта инструкция — для тех, кто сделал **fork** этого репозитория себе, чтобы
запустить систему для своего клуба/соревнования со своей базой данных и
своим токеном судьи.

> ⚠️ **Важно:** после форка в файле `config.js` останутся ключи Supabase
> **оригинального** автора (URL и anon key). Пока вы не замените их на свои
> (шаг 3в), ваша страница будет писать/читать данные из **чужой** базы.
> Обязательно выполните все шаги ниже, прежде чем показывать ссылки судье
> и зрителям.

## 1. Fork репозитория

1. Открыть репозиторий на GitHub → кнопка **Fork** (правый верхний угол)
2. Оставить имя `mushketon-final` (или поменять — не влияет на работу)
3. **Create fork** — репозиторий появится у вас в аккаунте:
   `https://github.com/ВАШ_ЛОГИН/mushketon-final`

> Свой репозиторий с нуля тоже подойдёт — тогда просто скопируйте файлы
> проекта в новый **Public**-репозиторий и переходите к шагу 2.

## 2. GitHub Pages

1. Ваш форк → **Settings** → **Pages**
2. Source: **Deploy from a branch** → `main` / `(root)` → **Save**
3. Через ~1 минуту страницы доступны:
   - `https://ВАШ_ЛОГИН.github.io/mushketon-final/judge/`
   - `https://ВАШ_ЛОГИН.github.io/mushketon-final/scoreboard/`

## 3. Supabase (своя база — обязательно)

Использовать базу оригинального автора **нельзя** — она обслуживает его
соревнования, и своими действиями вы будете стирать/менять его данные.
Нужен отдельный проект Supabase.

1. Зарегистрироваться на [supabase.com](https://supabase.com)
2. **New project** → название → **Create** → подождать ~2 минуты

### 3а. Настройки API

**Project Settings → API → Data API:**
- Enable Data API: ✅ ON
- Automatically expose new tables: ❌ OFF
- Enable automatic RLS: ✅ ON

### 3б. Создать таблицы, политики, права и Realtime

**SQL Editor → New Query** → вставить всё содержимое `sql/supabase_setup.sql`

⚠️ В первой строке заменить `REPLACE_ME` на свой секретный токен (это будущий
токен судьи — придумайте длинную случайную строку) → **Run**

> Этот один SQL делает всё сразу: таблицы, RLS-политики, `GRANT`-права и включение
> Realtime. Ручные шаги в консоли не нужны.

> ℹ️ **Уже есть работающая база?** Столбцы таймера уже есть в этом скрипте,
> но если таблица `competitions` уже существует и содержит данные,
> повторный запуск `supabase_setup.sql` её не трогает (`CREATE TABLE IF NOT EXISTS`),
> но необходимые поля таймера также не появятся. В этом случае выполни
> `sql/add-timer-fields.sql` отдельно — он безопасно добавит три поля таймера
> (`ADD COLUMN IF NOT EXISTS`) без утраты данных.

### 3в. Вписать СВОИ ключи в `config.js`

В репозитории уже лежит `config.js` — но в нём ключи **оригинального**
автора (см. предупреждение в начале документа). В нём же лежит файл-шаблон
`config.js.example` — на него можно ориентироваться при заполнении.

В своём форке открыть корневой файл `config.js` (например, через веб-редактор
GitHub — карандаш ✏️ на странице файла) и заменить значения на свои:

```js
window.MUSHKETON_CONFIG = {
  SUPABASE_URL: '...',       // Project URL (Settings → API) вашего проекта
  SUPABASE_ANON_KEY: '...'   // anon public key вашего проекта
};
```

Свои ключи смотрите в новом Supabase-проекте: **Settings → API**.

> Ключи в одном месте — обе страницы (`judge/`, `scoreboard/`) читают
> его через `../config.js`. anon key публичен по дизайну — защита через RLS.
> Закоммитьте изменение (**Commit changes**) — GitHub Pages подхватит его
> автоматически в течение минуты.

> ℹ️ **Разворачиваете проект с нуля (не форк)?** Скопируйте `config.js.example`
> в `config.js` в корне репозитория и впишите туда свои ключи — так `config.js`
> с самого начала не будет содержать чужих значений.

## 4. Проверка

1. Открыть `https://ВАШ_ЛОГИН.github.io/mushketon-final/judge/?token=ВАШ_ТОКЕН`
   (токен — тот, что вписали вместо `REPLACE_ME` в шаге 3б)
2. Создать тестовое соревнование, ввести пару очков
3. Открыть `https://ВАШ_ЛОГИН.github.io/mushketon-final/scoreboard/` в
   соседней вкладке — убедиться, что данные появляются мгновенно

Если данные не появляются — проверьте, что `config.js` указывает именно на
**ваш** проект Supabase (шаг 3в), а не на URL из исходного репозитория.

## 5. Свой токен судьи

Токен из шага 3б — не меняйте на дефолтный `REPLACE_ME` и никому не
показывайте, кроме судьи. Как сменить токен позже — [usage.md](usage.md#смена-токена-судьи).
