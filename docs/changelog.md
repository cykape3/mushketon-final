# История изменений и идеи

## Индивидуальный финал (второй тип соревнования)

- Новое поле `competitions.type` (`'pairs'` / `'final'`), несвязанные соревнования
- Геттеры серий (`seriesLabels()`/`seriesCount()` в judge, `seriesCountFor()` в scoreboard)
  выбирают набор колонок по `competition.type` вместо глобальных констант
- Новые колонки `s7`, `s8`, `s9` в `shooters` — 7 раундов по 2 выстрела после квалификации (`s1`, `s2` — 5+5)
- Модал создания соревнования — табы «Пары» / «Индивидуальный финал», по умолчанию активен финал
- Абсолютно не реализовано в коде: логика выбывания стрелка в финале — рейтинг
  всегда просто сортируется по сумме очков, судья сам определяет выбывание — см. правило
  отсечки в `docs/usage.md`
- SQL (`supabase_setup.sql`) пересобран с нуля (`DROP TABLE` + `CREATE TABLE`) — токен судьи (`get_judge_token()`) не затронут, ссылка судьи осталась работающей

## Что сделано

- Настроен GitHub репозиторий и GitHub Pages
- Настроен Supabase: таблицы, RLS, Realtime, GRANT права
- Авторизация через токен в URL (без email, без формы входа)
- Scoreboard с Realtime подпиской (WebSocket, без polling)
- Страница судьи: модал участников, таблица ввода, рейтинг внизу
- Логика пар: щит 1+2, 3+4 (не два стрелка на одном щите)
- Фиксированный формат: 4 пары / 8 стрелков (щиты 1–8)
- Заголовки серий: 5 5 5 3 3 3 (количество выстрелов в серии)
- Enter → переход вниз по строкам; Tab → следующий столбец
- Рейтинг на странице судьи без дублирования данных
- В строке рейтинга на странице зрителей (scoreboard) рядом с именем каждого
  участника показывается его индивидуальная сумма в скобках (например,
  «Иванов (24.0) / Петров (18.0)»); если серии ещё не введены — скобки не
  показываются. На странице судьи (judge) индивидуальные суммы в рейтинге
  не выводятся — только имена, чтобы не перегружать таблицу

## Упрощение эксплуатации

- Единый `config.js` в корне: ключи Supabase в одном месте (были в двух HTML)
- `supabase_setup.sql` делает всё сразу: таблицы, RLS, GRANT, Realtime (убраны ручные шаги)
- все SQL-скрипты собраны в папке `sql/`: `supabase_setup.sql`, `add-timer-fields.sql`, `rotate-token.sql`
- `sql/rotate-token.sql` — готовый сниппет смены токена
- Документация приведена к текущей модели (`shooters`, токен в URL, 4 пары / 8 человек)
- scoreboard: авто-реконнект при обрыве связи + полноэкранный режим

## Таймер

- Судья запускает обратный отсчёт (250 с или 50 с) на своей странице
- Страница зрителей показывает тот же таймер синхронно через Realtime
- Состояние хранится в БД — при перезагрузке страницы зрителей таймер подхватывает актуальное состояние

## Сохранение и восстановление соревнований

- Кнопка **«Соревнования»** (серая) в заголовке страницы судьи: открывает список последних 10 стартов (newздные сверху)
- Превью в списке: дата+время создания, тип, первые 3 фамилии (сорт по щиту); текущее соревнование помечается, кнопка «Восстановить» не показывается
- Восстановление: смена `is_active` с проверкой результата и перерисовкой страницы судьи; табло перечитывается без перезагрузки
- Старые сессии не удаляются — всегда доступны через кнопку «Соревнования»
- Новая колонка `competitions.created_at` (тип `timestamptz`) — для сортировки списка и детерминированного выбора активной сессии при нескольких активных
- Табло зрителей автоматически переключается на восстановленную сессию (подписка `UPDATE competitions` без фильтра по `id`)
- Истёкший таймер (запущенный час назад) не показывается на табло и у судьи при восстановлении
- Миграция для живой базы: `sql/add-created-at.sql`
